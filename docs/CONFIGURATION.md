# Configuration Reference

## Environment Variables

Configure devcontainer-nginx via environment variables (with defaults):

```bash
BASE_DOMAIN=local.dev-gutools.co.uk
DOCKER_SOCKET=/var/run/docker.sock
NGINX_CONFIG_PATH=/etc/nginx/conf.d/generated.conf
TLS_CERT=/etc/nginx/certs/wildcard.crt
TLS_KEY=/etc/nginx/certs/wildcard.key
DEBOUNCE_MS=500
LOG_LEVEL=info
```

### BASE_DOMAIN

The base domain for generated hostnames.

Default: `local.dev-gutools.co.uk`

Example: with `BASE_DOMAIN=local.dev`, container `myapp` becomes `myapp.local.dev`

### DOCKER_SOCKET

Path to the Docker Engine socket.

Default: `/var/run/docker.sock`

Typically mounted from the host as: `-v /var/run/docker.sock:/var/run/docker.sock:ro`

### NGINX_CONFIG_PATH

Path to the generated Nginx configuration file.

Default: `/etc/nginx/conf.d/generated.conf`

This file is generated by the controller and contains all discovered routes.

### TLS_CERT

Path to the wildcard TLS certificate.

Default: `/etc/nginx/certs/wildcard.crt`

Typically mounted from the host:
```bash
-v ${HOME}/Library/Application\ Support/mkcert/wildcard.crt:/etc/nginx/certs/wildcard.crt:ro
```

### TLS_KEY

Path to the wildcard TLS private key.

Default: `/etc/nginx/certs/wildcard.key`

Typically mounted from the host:
```bash
-v ${HOME}/Library/Application\ Support/mkcert/wildcard.key:/etc/nginx/certs/wildcard.key:ro
```

**Security Note:** Never commit private keys to git. Keep them local to your machine.

### DEBOUNCE_MS

Debounce period for Docker events (in milliseconds).

Default: `500`

Docker can emit several related events for a single logical operation (e.g., a container start). The debounce period coalesces these events into a single reconciliation pass. Increase if you see thrashing; decrease for faster updates.

### LOG_LEVEL

Logging level (not yet fully implemented).

Default: `info`

## Docker Compose Example

```yaml
services:
  devcontainer-nginx:
    build: .
    image: devcontainer-nginx:local
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - "${HOME}/Library/Application Support/mkcert/rootCA.pem:/certs/rootCA.pem:ro"
      - "${HOME}/Library/Application Support/mkcert/rootCA-key.pem:/certs/rootCA-key.pem:ro"
      - "./certs:/etc/nginx/certs:ro"
    environment:
      BASE_DOMAIN: "local.dev-gutools.co.uk"
      DOCKER_SOCKET: "/var/run/docker.sock"
      TLS_CERT: "/etc/nginx/certs/wildcard.crt"
      TLS_KEY: "/etc/nginx/certs/wildcard.key"
      DEBOUNCE_MS: "500"
    restart: unless-stopped
```

## DNS Configuration

The proxy does not manage DNS. Configure your DNS infrastructure to provide:

```
*.local.dev-gutools.co.uk → <your-machine-ip>
```

For local testing on macOS, you can add to `/etc/hosts`:

```
127.0.0.1 myapp.local.dev-gutools.co.uk
127.0.0.1 devcontainer-nginx.local.dev-gutools.co.uk
```

Then test with:

```bash
curl -k https://myapp.local.dev-gutools.co.uk
```

## Homepage Endpoints

The proxy exposes a dedicated homepage hostname:

`https://devcontainer-nginx.<base-domain>` and `http://devcontainer-nginx.<base-domain>`

Available paths:

- `/nginx.conf` → Base Nginx configuration
- `/generated.conf` → Generated routes file
- `/nginx/config` → Combined output of both files
- `/containers` → List all containers with active routes
- `/container/{name}` → Nginx server block(s) for a specific container

Example:

```bash
curl -k https://devcontainer-nginx.local.dev-gutools.co.uk/containers
curl -k https://devcontainer-nginx.local.dev-gutools.co.uk/container/myapp
```

## Container Labels (Optional)

While labels are **not required**, you can use them for explicit control:

### devcontainer.hostname

Override the generated hostname:

```bash
docker run -d \
  --name myapp \
  --label devcontainer.hostname=custom-name \
  -p 3000:3000 \
  your-app:latest
```

Results in: `custom-name.local.dev-gutools.co.uk`

### devcontainer.application.port

Explicitly specify which port to proxy:

```bash
docker run -d \
  --name myapp \
  --label devcontainer.application.port=3000 \
  -p 3000:3000 \
  -p 8080:8080 \
  your-app:latest
```

Without this label, the proxy would be ambiguous and skip the container.

### portsAttributes (Dev Containers)

In `devcontainer.json`:

```json
{
  "forwardPorts": [9100, 1234],
  "portsAttributes": {
    "9100": { "label": "backend" },
    "1234": { "label": "frontend" }
  }
}
```

Each labeled port becomes a separate route:
- `myapp-backend.local.dev-gutools.co.uk` → port 9100
- `myapp-frontend.local.dev-gutools.co.uk` → port 1234

## Health Checks

The container includes a Docker health check that verifies Nginx is serving HTTPS:

```bash
docker inspect devcontainer-nginx | jq '.State.Health'
```

Expected output when healthy:

```json
{
  "Status": "healthy",
  "FailingStreak": 0,
  "Iterations": 1
}
```
